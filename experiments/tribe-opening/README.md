# 《万界文明》河谷流民开局实验 · 自主战棋 0.1

独立入口：`experiments/tribe-opening/index.html`。不修改正式 `game.html` 和世界权威数据。

## 目标
验证：简单确定性的棋子 AI 是否产生可供玩家预测、干预与长期构筑的战棋微循环。

## 运行
本实验已拆出 ES 模块，`file://` 双击不再可用，请在仓库根目录起一个 http 服务：

```
python -m http.server 8000
# 打开 http://localhost:8000/experiments/tribe-opening/
```

自动化验证：

```
node --test tests/tribe-opening.test.js
```

## 文件分工
| 文件 | 职责 |
|---|---|
| `tribe-sim.js` | 纯规则内核：地图、单位、BFS 寻路、指令生命周期、两种文明规则、日推进。无 DOM，可被 `node --test` 直接导入 |
| `app.js` | Canvas 绘制、按钮、点击选择与下令；只读内核状态，不持有权威 |
| `index.html` | 页面骨架与样式，加载上面两个模块 |

## 操作
- 点击“部署猎团 / 部署守卫”，再点营地周围高亮的合法格完成部署；部署点即该战团的**驻守点**。
- 点击我方“猎”“卫”选中，点击右侧“移动至此 / 指定攻击 / 坚守此地”，再点地图目标；“恢复自主”移除指令。
- 暂停/继续、0.5×/1×/2×/4× 速度以及固定种子重开（一步 = 一个 tick，基础 0.8 秒；0.5× 慢速约 1.6 秒一步）。
- 首次遇见捕食者时出现二选一行为构筑：“警戒本能”使猎团在 3 格内发现捕食者时撤离、威胁离开后自动恢复；“集群狩猎”让猎团与友方保持 2 格协同（离队超过 4 格才归队），协同命中额外造成 2 点伤害（日志会打印协同 +2）。
- 每 18 次模拟步进入新的一天，结算人口的食物消耗，并视情况补充野生单位。

## 2026-10-25 修复记录（本分支）
原版本是单文件内联脚本，本次只做缺陷修复与可测试化，未扩展美术，也未并入 `game.html`。

| 问题 | 根因 | 修复 |
|---|---|---|
| 棋子寻路卡死 | `stepToward` 只做贪心一步：仅当某个相邻格「更接近目标」才移动，遇到水面或其他单位就永久停在原地，指令也不收尾 | 改成六角网格 BFS 寻路（`findPath`），可绕开水面与占位；无路可走时明确放弃并记录日志 |
| 移动到被占用的格子永远到不了 | 目标格被单位占据时 `walkable` 为 false，距离永远不为 0，`order` 永远停在 `move` | 目标被占时改走「与目标相邻的可达格」，到位即收尾；加 `stall` 看门狗，连续 4 步无法推进就恢复自主并记日志 |
| 玩家干预看似无效 | 上一条的表现：下令后棋子原地不动，也不会回退自主，玩家无法判断命令是否生效 | 指令有明确生命周期：move 抵达/放弃、attack 目标消失或不可达、hold 抵达后驻守，全部写日志 |
| 集群狩猎构筑不生效 | 触发条件是「2 格内有友方」，但场上只有 1 支猎团、守卫又驻守营地不动，实战中几乎永不触发；且它只加伤害，猎团本身没有靠近友方的行为 | 集群狩猎下猎团会主动向最近友方合流（位移层面可观察），协同命中时打印「集群狩猎 +2」日志 |
| 构筑机会出现时猎团往往已经死了 | 猎团会主动扑 7 血 / 2 攻的狼，6 血换不过，默认对局里常在构筑前就被打散，装上规则也没有对象可作用 | 加生存判断：只有血量 ≤ 狼攻击 ×2 且狼仍然很硬时才脱离，不再自杀式扑击 |
| 警戒本能逃到营地后原地不动 | 撤离只是朝营地走，狼仍在 2 格内时既不还击也不离开 | 改成在 2 步可达范围内选「离威胁最远、其次离营地最近」的落脚点撤离，威胁离开 3 格后自动恢复自主，并记录「猎团本能撤离捕食者」 |

控制台：Chromium 实跑（加载、安装两种规则、移动/攻击/坚守/恢复自主、重开、1×→4× 速度、25 秒持续运行共 85 步）未出现 `error`、未捕获异常或 `console.warn`。原版本也未复现 JS 运行时异常——上表都是逻辑缺陷，不是抛错。

|---|---|---|---|

| 相邻友方时对鹿的一击 | 2 点（鹿剩 1 血） | — | 4 点（鹿当步死亡） |

## 2026-10-25 第二轮：部署机制 + 行为规则表（验收项 3/5/6）

### 部署机制
- **范围**：营地 2 格内、非水面、未被占用；范围外/水面/占用/食物不足都会被拒绝并给出原因，且不写入任何状态。
- **成本**：猎团 10 食物、守卫 12 食物。基础生命/攻击数值一律未改。
- **驻守点**：部署点写入 `unit.post`，此后该棋子的「家」就是落点（初始两支仍以营地为驻守点）。玩家换位置 = 换它的防守/狩猎半径。
- **自主运行**：部署后 `order = auto`，不再接受逐格微操以外的新行为逻辑。

### 行为规则表（显式、公开、可测试）
玩家指令（move / attack / hold）永远最优先，其下按表取第一条命中的规则，命中结果写入 `u.action` 并显示在棋子下方与选中面板。

| 猎团 | 守卫 | 狼 | 鹿 |
|---|---|---|---|
| 1 `rule.caution.flee` 警戒本能撤离（3 格内） | 1 `defend.engage` 驻守点 3 格内有狼则接敌 | 1 `raid.chase` 3 格内追人 | 1 `flee.human` 相邻则逃 |
| 2 `survive.disengage` 血少且狼硬则脱离 | 2 `post.return` 回驻守点 | 2 `raid.approach` 逼近营地 | 2 `idle` |
| 3 `rule.pack.cohesion` 离友方 >4 格时归队 | 3 `idle` | 3 `idle` | |
| 4 `hunt.prey` 自主狩猎 | | | |
| 5 `post.return` 回驻守点 | | | |
| 6 `idle` | | | |

规则表以 `HUNTER_RULES` / `GUARD_RULES` / `WOLF_RULES` / `DEER_RULES` 导出，`selectRule(world, unit)` 可只读预测当前会命中哪条，测试直接断言顺序。

**滞回锁存**：归队只在「离友方 >4 格」时开始、「≤2 格」时结束（`u.cohesion`）。第一版用单一阈值 2 时，猎团会在「追猎物」和「回队」之间每步来回切换、原地抖动，这条锁存就是为此加的；`tests/tribe-opening-deploy.test.js` 里有专门的反抖动断言。

### 部署位置的确定性对照（同种子 1117，`tests/tribe-opening-deploy.test.js` 13 项全通过）
| 对照 | 结果 |
|---|---|
| 接敌时间 | 部署 (2,-1) 比 (-1,1) 更早与狼交火（同一步进下前者先开火） |
| 协同加成 | 部署 (1,1)（离守卫 1 格）首击 4 点；部署 (2,-2)（离守卫 3 格）首击 2 点 |
| 防守距离 | 守卫部署 (2,-1)：狼第 5 步被击杀，最近逼近到距营地 3 格；部署 (0,2)：第 6 步击杀，狼逼近到 2 格 |
| 防守范围 | 狼距驻守点 2 格 → `defend.engage`；距 4 格 → `idle`（不出击） |
| 驻守点收束 | 被推离落点的守卫 10 步内回到部署点 (2,0)，不回营地 |

### 浏览器实测（Chromium，真实鼠标）
- 部署守卫到 (2,-1)：食物 54→42、`deploys=1`、落点即驻守点、选中面板显示「行为 待命 ｜驻守点 (2,-1) ｜本局部署」。
- 三个非法点击全部被拒绝，食物与部署数不变：`超出部署半径（营地 2 格内）` / `水面不可部署` / `该格已被占用`。
- 同种子 54 步 A/B（不部署 vs 部署守卫(2,-1)+猎团(1,1)）：**人口 15 vs 20**、存活战团 1 vs 4、食物 60 vs 36。也就是说 22 点食物换来了整局不损人口。
- 完整一局：部署两支 + 装集群狩猎，跑到第 2 日，`defend.engage` / `hunt.prey` 行为标签在场上可见；控制台 0 error / 0 warn。

`node --test tests/*.test.js` 全量 **101 个测试通过**（原 74 + 部署 13 + 军事 14）。

## 2026-10-25 第三轮：军事子系统骨架（兵营 / 驻军池 / 方针 / 命令延迟 / 军粮）

对应《军事系统设计总结 V1.0》里"军事生产 → 驻军与部署 → 自主战棋 → 玩家干预"四环节的最小可跑版本。全部是实验常量，未定稿。

### 兵营：军事生产与组织节点，不是部队上限
- 兵营是**实体建筑**：占一格、阻挡通行、同格不可叠放，不能建在水面。
- 训练：`orderTraining` 排队 → 开始训练即扣食物（猎团 6 / 守卫 8）→ 猎团 6 步、守卫 9 步后**进入驻军池**。
- 驻军池里的部队**不占格、不上地图**（这就是"训练完先驻军，而不是凭空出现在战场上"）。
- 出营 `deployFromGarrison`：落在兵营相邻可达格，落点写为该部队的驻守点；兵营本身不提供"能带几支部队"的上限。

### 四条方针（兵营自动运行）
| 方针 | 触发条件（只看距离与计数） |
|---|---|
| 驻守本地 | 据点 3 格内出现捕食者才出营 |
| 边境巡防 | 据点 3 格内没有我方战团时出一支 |
| 前线增援 | 在野战团少于 2 支时补员 |
| 保留预备 | 永不自动出营，只等玩家手动 |

### 命令延迟：干预是例外，不是配额
- `world.orderDelay` 是命令在途步数（正式试玩 = 2；离营超过 4 格再 +1）。
- 在途期间棋子**继续按自主规则行动**——这就是"自动是默认态"的机制表达。
- 选中棋子时会显示「指令在途 N 步」。
- P4 对照（`tests/tribe-opening-military.test.js`）：同一次救场，即时命令臂撤走只掉少量血，延迟 3 步臂多挨一次咬。两臂都存活，没有用死亡作弊。

### 军粮与同屏预算
- 每支**在野**我方战团每天额外消耗 1 食物（驻军池里的不算）。
- 同屏棋子预算 `fieldCap = 24`：达到后出营排队，不再实例化。

### 边界
- 战斗中的碰撞、阻挡、包围与地形规则**仍未设计**；现在的阻挡只来自"一格一单位 + 兵营占格 + 水面"。
- 战团编组、军团规模、不同文明的军事机制**未开始**。
- 兵营目前只有一座（开局营地北侧），位置战略价值还没有做成可选布局。

## 重要边界
这是 **浏览器 Canvas 独立玩法实验**，不是成熟的 Three.js 微雕游戏、不具备存档、完整经济、其它文明、远征、卡牌生命周期、完整教学或正式流程。程序中的 AI、食物与战斗系临时规则。本分支只做了自动化测试与一次 Chromium 实机复验，**不等于真人玩法验收**。不要把“已推送 GitHub”误写为“已可玩验收”。

## 给开发者的下一步验证
1. 真人试玩：确认 3 分钟内能够遭遇狼、收到构筑机会，并能感到两种规则的差异；记录首次干预时间与无效操作。
2. 继续检查：野兽再生节奏、多单位挤在窄缝时的碰撞死锁、远程攻击掩体、时间尺度。
3. 部署成本（10 / 12 食物）与部署半径（2 格）都还是实验常量：需要真人试玩判断「值得为防守花掉多少食物」，以及半径 2 是否让位置选择的空间太小。本轮实测里，狼的来袭路线几乎覆盖整个部署环，正面与背面的差距只有 1 步 / 1 格（见上表）；如果想让「位置」更有决策重量，优先调半径而不是加 AI 复杂度。
4. 集群狩猎目前依赖「友方在 2 格内」；若要扩展成多猎团协同，需要重新设计合流与目标选择，而不是简单提高加成。
5. 经过玩法验证后再将规则内核与正式六边形世界共享，**不要直接融合两套世界状态**。


## 2026-10-26：真实流民最小循环（实验，尚未实机复验）
- 新增 `civilians.js`，每位流民有独立 ID、六角格位置、采集/返程/建设状态；轻量生活层与军事碰撞层分离。
- 开局 20 名流民，没有凭空生成的猎团/守卫；在河谷营地周围可见居民活动。
- 采集者走到附近资源格，带回食物；建设者累积建设进度，陆续形成简易住所（可见）；这不是完整生产或住房系统。
- 兵营训练开始时从居民中抽调真实人数：猎团 4 人，守卫 5 人。预备队从实体兵营相邻格出营，不能在任意格召唤。
- 旧版独立直接部署按钮在流民模式禁用；旧 deploy API 保留用于兼容部署实验和对照测试。
- 新测试 `node --test tests/tribe-opening-civilians.test.js`，全量使用 `node --test tests/*.test.js`。
- **待验收**：本次通过远端 GitHub 修改，尚未本地执行 node 测试或 Chromium 操作；开局死亡、食物收支、显示密度和行为节奏需要本地实机核对。

## 地图设计决策（待讨论）
当前地图仅半径 5、91 个六角格，用于战团行为验证。不要直接按相同粒度扩大到整片大陆。
建议世界使用：区域图（宏观经济/交通/文明扩张）→ 局部六角地图（兵营/野兽/部队实体）→ 个体生活表现（居民 ID 与位置，按需绘制）。
保留真实道路、河流、山口和行军耗时；远处区域采用低频更新和抽象人口，而非每个居民始终逐步寻路。
暂不把这一地图方案写进正式主线权威状态，需先验证观察、导航与局部进出的一致性。
