# GAME-QUALITY-001：游戏开发质量反馈与持续改进协议

**生效范围：WanjieEngine /《万界文明》所有 AI 与人工开发活动。长期有效，直接在 main 维护。**

## 一、身份与最高原则
开发者也是成果的第一责任评审人。目标不是仅完成需求或通过测试，而是提高最终游戏质量与玩家体验。
**设计 → 实现 → 运行 → 观察 → 评估 → 发现问题 → 改进 → 再验证**。
禁止将“代码提交”“测试通过”“功能存在”等同于“开发完成”。技术正确性必要但不充分。

## 二、每次玩家可感知改动后的实际反馈
根据工作规模对下列维度进行检查，并区分**代码存在、测试通过、实际可用、体验良好**：
1. **功能**：符合原始需求吗？正式流程可达吗？能与其他系统互动吗？有没有多余复杂度？是否存在更简单的实现？
2. **视觉/美术**：统一性、轮廓、材质、光影、颜色、空间、视觉重点及信息表达是否达标？是否把程序占位伪装成正式资产？与成熟商业游戏相比明显缺什么？
3. **布局/交互**：屏幕占比、空白、UI 密度、可发现性、操作次数、镜头、缩放、空间比例、操作反馈是否合理？重要改动必须检查真实窗口和运行截图。
4. **游戏性/玩家体验**：玩家为什么愿意使用？有无真实选择/代价、明确后果、反馈、目标与成长感？有哪些无聊、困惑、重复或挫败点？不得以理论深度替代实测。
5. **技术/架构**：技术方案、性能、复杂度、重复系统、迭代成本、兼容性。区分引擎/实现/美术资源/玩法设计的根因；定位之前不得轻率更换引擎或大规模重写。

## 三、外部质量参照
重要视觉、交互、玩法工作应尽可能研究 2–3 个相关成熟游戏。明确：对方为何优秀、己方差距、根因（技术/美术/设计/资源）、低成本可借鉴点、不适合的效果、必须立即解决与可接受的差距。不得复制受版权保护的素材。无法访问或未研究时明确写“未调研”，不得冒称完成。

## 四、强制自我批评
主动寻找至少一个**有证据**的不足；不准为了凑数编造问题。质疑是否仅让功能运行、只完成字面需求、以复杂结构掩盖质量、过度信任测试、忽略实际表现。证据可为截图、录屏、操作、状态、性能数据、代码及测试。无法亲验即标记“未验证”。

## 五、问题优先级
- **P0 阻断**：无法运行、存档损坏、核心流程不能完成或严重数据错误。
- **P1 重大**：核心玩法明显不好用、重大空间或视觉失准、关键交互违背需求。
- **P2 明显缺陷**：局部美术不统一、UI 不清晰、操作繁琐、动画/节奏欠佳。
- **P3 优化**：细节润色、低优先级性能/装饰建议。

每个重要问题记清：现象、证据、疑似根因、玩家影响、最小有效修复、验收方法。优先 P0/P1；尚不能判断严重程度的应标记待实测并给出依据。

## 六、每轮质量反馈（A–F）
A. **本轮实际完成**：实现并验证了什么；分离规划、实验、未验证事项。
B. **验证情况**：具体测试、启动、实际操作、截图、性能，以及未执行部分。
C. **质量评价**：功能、美术、布局、交互、玩家体验、性能、代码；有证据才能评分，未验证不评分。
D. **主要问题**：依影响程度列 1–5 项，不以琐碎问题掩盖关键缺陷。
E. **外部对标**：若有研究，说明主要差距及当前可缩小部分；否则标“未调研”。
F. **下一轮改进**：先解决什么、为什么、最小修改以及可证明改进有效的结果。

## 七、质量发现进入下一轮
报告不是装饰。重大问题优先于新增功能：镜头/地图问题先修布局，移动僵硬先修运动，画面粗糙先修资产/表现，系统玩法无趣先观察节奏反馈。选择暂不修复必须写明原因与接受的风险。禁止用更多功能回避已暴露的缺陷。

## 八、适度评估
小修复简短检查；普通功能评估相关维度；重要视觉/UI/玩法必须实际体验；大版本跨系统综合评估。反对形式主义与官僚式长报告。

## 九、持续记录
统一使用 [QUALITY_LOG.md](QUALITY_LOG.md)，记录每项主要缺陷：优先级、首次发现提交或版本、证据、状态、修复提交、复验结果。已修复问题保留简短历史，防止回归。不单独建设复杂平台。

## 十、执行铁律
1. 功能完成不等于质量合格。
2. 测试通过不等于体验良好。
3. 开发者主动发现不足。
4. 以实际运行结果判断质量。
5. P0/P1 优先于新功能。
6. 允许承认成果欠佳，不得用漂亮报告掩盖。
7. 开发目标是提高体验，而不是累积代码。

## 工程适用说明
- 所有工作在唯一长期主线 `main` 记录，质量审查并不授权删除历史分支或覆盖模型。
- 新增/修改玩家可感知代码的提交，应对应简洁 A–F 报告；若没有运行机会，清晰记录代码审查与待实测风险。
- **状态标签**：`CODE_ONLY`、`TESTED`、`PLAYED`、`ACCEPTED`，不得越级宣称。
