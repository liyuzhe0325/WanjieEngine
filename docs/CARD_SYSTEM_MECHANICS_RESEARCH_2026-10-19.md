# 《万界文明》卡牌机制骨架与研发方法（2026-10-19）

> **设计记录，不是已实现代码或正式卡池。** 衔接 [游戏设计宪章](./GAME_DESIGN_CANON.md) 与 [10月18日玩法讨论](./GAMEPLAY_DESIGN_NOTES_2026-10-18.md)。
> 标记：**[确认]** 用户明确认可；**[方向]** 用户接受探讨、尚待检验；**[实验]** 独立原型或例子；**[待定]** 不得默认定稿。

## 1. 当前最高优先级：先骨架，后填牌，再测试并大量删减

**[确认]** 采用成熟卡牌游戏常见的迭代方法：
**机制骨架 → 极少量占位内容 → 可玩/可复现实验 → 玩家反馈与数据 → 大量删减/合并 → 再扩充。**

- 不是每提出一个“有趣想法”就新增一张卡、一种专门效果或一个 UI 区域。
- 单卡**最好一句话、一个主作用**；复杂度来自卡与实体属性、地形、世界状态、卡与卡之间的组合，**不能通过把大量特判偷偷藏入世界引擎来假装简单**。
- 卡既要有独立价值，也应创造“何时用、用于谁、留不留”的取舍；避免卡牌仅仅变成文明6政策/科技/基础管理按钮的包装。
- 普通采集、生产、物资整理等常规行政操作通常是文明模拟和面板逻辑，不应强行逐动作要求一张牌。
- 科技可以属于卡牌互动的一部分，但**科技、政策、天赋与可操作卡牌要分辨概念**；领主天赋不等同于所有领主增益牌。

## 2. 先设计卡牌交互的世界对象及数据，再设计卡牌

**[确认/方向]** 先建能被牌作用的客观世界；同牌依环境表现不同。对象域：
1. 领主；2. 人口/人物；3. 地块/生态/天气；4. 单位/组织；5. 建筑/设施；6. 物资/生产/运输；7. 文明/势力/外交关系；8. 卡牌/牌源/机制。
这些是**功能域，不一定是八个互斥代码类**。

- 数据组成：身份、位置/状态、可执行能力、关系（邻接、归属、物流、挂靠）、持续规则；只给对象存在意义的属性，不做“万能属性袋”。
- **世界真实状态**与玩家**已知/推测信息**分离；侦察有价值，敌人不能无条件读心。
- 通用动作候选：创建、移除、移动、转移、连接、断开、附加、复制、转化、触发。动作必须有合法性、实体差异、权限与成本检查。
- 火源与可燃物、湿度、风、道路/运输与补给关系、组织指挥与可用人口等属于世界规则；「点燃」无需逐地形写专门效果。
- 空间连接与网络、资源地点与运输需实际存在，不可凭“全局库存”瞬移补给。宏观任务通过组织模型下推，而非逐个点击每个人。
- 这些字段表是**待缩减的数据字典候选**，不是要求首轮实现全部复杂模拟。

## 3. 卡牌粒度：数字、作用单位、时间必须区分

**[确认]** 用户提出借鉴扑克牌使用**数字表示粒度**，**并非**主要想把游戏做成凑对子/同花顺。
- 候选形式「探索 2 / 探索 4」「集结 3」：**同一条基础规则 + 数字表达操作量级/额度**；避免仅因文明成长大量增加不同名字的“全国版”卡。
- **[待定]** 数字究竟是数量、强度、范围、任务投入额度，是否有统一尺度、数值区间（如1-10），以及跨卡组是否可比，**均未定稿**。先比较具体可读性。
- 区分 **作用规模**、**规则复杂度**、**生效/执行时长**。即时点燃可能导致长期火灾；提交一次远征计划不代表牌要永久占队列。
- 卡牌放大应优先依赖真实**组织成员关系、网络与目标能力**，而不是“人数随时代自动乘10”。数字增加可能有成本、风险，不能默认大数总更好。
- **[方向]** 拆分/合并数字牌是可试机制，但不得默认免费、无成本、无限产生额外行动；需验证额度守恒和机会经济。

## 4. 广泛牌文化研究：灵感，不是全部上线

研究/讨论参考（仅用于设计启发，不是历史复刻）：扑克、塔罗（大小阿尔卡那与象征）、花札（季节及成组收益）、印度 Ganjifa（不同花色的阶序）、万智牌（简洁与透镜式深度）、杀戮尖塔（机会成本、组牌）、Dominion（抽牌/回收）、皇室战争（资源与卡牌机会约束）、Balatro（简短规则乘以持久组合）、Marvel Snap（场地交互）、Innovation（覆盖/展开/图标）、Gloomhaven（多用途及生命周期）、Monster Train（持续实体构筑）、Everway（情境解释）、Netrunner（隐藏信息）。
- **[确认/方向]** 取**数字可读、概念可组合、环境/目标/摆放位置有意义**等思想；不要一次塞进花色、正逆位、牌阵、同花顺、特殊阶序或大量符号。
- **[实验]** “数字牌＋概念/机制牌＋长期载体牌”是可验证的原型分类，并非正式互斥卡型。
- **[待定]** 牌型奖励、概念牌是否不带数值、改变花色、牌位关系、数字拆合等只保留为可测试候选。

## 5. 出牌与宏观任务

**[方向，用户认可继续]** 统一交互语法：**选牌（点击或拖拽）→ 选合法目标 → 展示世界条件与结果预览 → 确认提交**。选择、预览、取消时不消耗牌；提交后按牌生命周期进入即时结算、筹备/队列或长效安装。
- 目标可以是地块、建筑、部队、组织、领主、文明、**另一张卡、正在筹备的战略计划**。
- 卡牌操作不是只将一张牌从手牌甩到棋盘；多个目标、机制牌/排队修改、长期挂靠通过同一目标选择规则与适度工作台实现。
- **宏观行动**：一张牌可以选择文明、地区、组织网络或敌对势力为目标。出牌创建**战略计划**（意图、范围、额度、优先级、筹备/执行/受阻状态），世界按组织指挥、资源、地理可达性与忠诚实际执行；不能因为“全国动员 7”就无条件召出不存在的军队。
- 玩家不必逐城点击完成全国计划；卡牌表述宏观意图，系统分解为真正的世界任务。计划本身可在合法条件下被其他牌操作。
- **[待定]** 精确队列撤回规则、资源提交点、组织压力算法、战略计划的数据结构、是否允许改令及消耗何时发生。

## 6. 信息架构与双重教学

**[确认]** 12张机制实验对新手“一下信息太多”；**玩家和开发者都需要新手教程**，并且信息需要有组织。保留深度、减少首次暴露，不是直接删除所有高级机制。

- **[方向]** 首屏围绕微雕棋盘、营地、少量关键状态和**最小可用的2–3张操作牌**；更复杂区域可隐藏、切换或主动展开；勿让满屏灰色未解锁按钮压迫新手。
- 学习序列候选：**观察营地 → 第一次出牌 → 认识数字差异 → 认识环境差异 → 初次长效安装 → 再逐步接触队列、组织负荷、概率波、机制牌/融合**。顺序可以随实际机会调整，非强制剧情。
- 玩家教学：“能做什么/选择哪个目标/为什么这样结算”；开发者教学：“对象属性、合法性检查、种子、结算依据、复现步骤”。**两种教学基于同一份机制事实**，避免两套说法失配。
- 常态三层信息：立即可见、按需详情、开发者调试。教学可跳过/重开，开发模式能查看全部候选、结算日志和测试。
- **[待定]** 实际布局、首次可见手牌数、每次教程花费、教程是否强制暂停，均需玩家测评。

## 7. 卡池示例的状态：候选不可冒充定稿

对话中提出过16张与24张远古卡池候选，如探索、迁徙、集结、营建、交涉、突袭、点燃、储藏、连接、附着、延展、复制、转化、传承、征召、窥探等；“部落议事、石器工艺、储藏技艺”被质疑过度接近政策/天赋或管理按钮。**不得直接将旧16/24张方案视为已批准的玩家开局。**

- **[实验]** 曾提供独立12张卡 HTML 实验，包含数字牌6张、概念牌3张、长效牌3张以及密林、河谷、山口、队列、拆分、合并、改道等功能。用户认为设计方向不错但信息量太大。它是**研发测试台，不是玩家首屏设计**，也未声明进入主仓库。
- **[方向]** “玩家模式只暴露必要内容、开发者模式展示全部实验结构”替代一次性展示12张牌。
- **[方向]** 新的 M0 机制测试夹具只需**4张**：**探索 2、点燃 1、集结 3、瞭望（长效）**，检验数字/环境/组织/安装；**不是正式起始牌池**，不强行照单生产。
- **[方向]** 小规模世界：河谷、森林、山口，少量可观察数据，最简牌源与一次完整出牌/执行/反馈链。特定 37 格/32人口等先前数字只是示意，不强制固化。

## 8. M0 测试、删减及验收

1. 机制层：合法目标、提交/取消、数字意义、环境反馈、行动队列、长效安装、最简卡牌机会循环。
2. 同种牌在不同地形能因世界规则获得**不同、可解释**的结果；不用每个地形写特殊卡面。
3. 数字大小可产生权衡；大型操作受物资、组织与实际目标限制，不能必然完全碾压小牌。
4. 新手能在短时间内完成首次出牌；帮助/开发者视图能定位结算原因。
5. 统计首次出牌时间、无效操作、保留/使用决策、不同环境下的选择、重复游玩是否有新策略；自动代理测试不等于真人有趣。
6. 无贡献、冗余、只能用难懂特判维持的卡/机制，应**删除或合并**；删去正式玩法不等于销毁设计过程记录。

**[待定]** M0 具体代码方案、卡片定义、抽牌概率、数字语义、组织负荷公式、真实玩家测试结果。此前的 HTML 或脚本原型**不代表**这些已获验证。

## 9. 不可遗漏的先前硬边界

- **概率波**：牌机会随机但可以受文明历史与构筑影响；不要临时让玩家能无限任意召唤所需行动牌。
- **领主本身可构筑**，但并非每张领主牌都只能是被动天赋。
- **本土既有强势力**与精英挑战优先；少量成长型对手；可以被灭国；未来网络天梯暂不开发。
- **世界必须真实运行**，日常生产通过面板/模拟进行，独立远征和战争等战略单位才在棋盘出现。
- **高质量微雕六边形棋盘**是核心舞台，卡牌工作台支持隐藏、排队、长期牌、挂靠与机制操作。
- **不能在没有足够验证时把所有候选功能装入正式版**；先做机制骨架、填少量内容、测试并删除。
