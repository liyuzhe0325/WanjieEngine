# 《万界文明》军事系统设计总结 V1.0

> 性质：**设计基准与决策记录**，不是实现清单。
> 来源：2026-10-25 与用户的军事系统专题讨论；用户提供 V1.0 主体，第二、六、七节含本轮讨论后的修正。
> 标记：[确认] 用户明确认可；[方向] 已接受方向、细节未定；[实验] 仅原型验证过；[待定] 尚未选择，不得当定稿。
> 权威入口仍是 [GAME_DESIGN_CANON.md](./GAME_DESIGN_CANON.md)。本文件若与其冲突，以用户后续决议为准。

## 一、核心定位

**[确认]** 军事棋子自主行动，玩家通过部署、指挥与战术干预创造优势；棋子能力与行为可由文明构筑改变。

**[确认]** 参考《皇室战争》《部落冲突》的自动单位机制，但**不照搬"凭空部署"**。

**[确认]** 军事系统分四个环节：军事生产 → 驻军与部署 → 自主战棋 → 玩家干预。干预可以发生在自主战斗**过程中**，不必等自动战斗结束。

## 二、棋子的自动行为

**[确认]** 不开发复杂战术 AI。棋子只需简单、明确、可预测的规则：

| 行为 | 内容 |
|---|---|
| 索敌 | 最近敌人、特定单位、建筑优先等 |
| 移动 | 依目标与地形自动寻路 |
| 攻击 | 满足射程、冷却后自动攻击 |
| 追击 | 按预设规则决定追击范围 |
| 防守 | 在指定区域内自主拦截 |
| 特殊行为 | 击杀成长、分裂、复生、冲锋等 |

**[确认]** 关键不是规则本身多聪明，而是**玩家能利用这些规律**：只会打最近敌人的士兵，可以用诱饵改道；棋子不自己规划包围，玩家用它的索敌与移动规律去完成包围。

## 三、玩家的军事操作

**[确认]** 玩家不逐次指挥普通攻击，但保留主动微操：

| 操作 | 功能 |
|---|---|
| 部署 | 决定哪支部队何时从军事设施投入战场 |
| 调动 | 指定目的地或行动区域 |
| 指定目标 | 临时改变攻击对象或优先级 |
| 坚守 | 限制棋子离开防守区域 |
| 撤退 | 让部队脱离战斗、返回安全位置 |
| 技能 | 关键时刻激活单位已有特殊能力 |
| 恢复自主 | 取消玩家指令，重新按默认规则行动 |

**[确认]** 普通军事命令**不要求抽到对应卡牌**。卡牌改变的是单位能力、行为机制与军事组织方式；少数特殊牌可提供额外战场干预。

## 四、棋子的来源

**[确认]** 绝大多数军事棋子只能由**真实的军事生产设施**产生：人类兵营训练、机械工厂组装、异虫巢穴孵化、冥河墓地复生、矮人要塞训练。生产机制因文明而异，但底层都是"军事棋子来源"。

**[确认]** 特殊英雄可通过事件、培养、招募获得，不必强制由卡牌召唤。

**[确认+边界]** 少数高级文明机制可允许特殊召唤/空降/传送，但：

- 例外必须**消耗指挥带宽以外的既有资源**（组织能力、前摇时间或稀缺材料），不能变成免费的第二条出兵通道；
- 例外必须**有可见前摇**（地图上出现传送门/尸堆发光），对手能提前反应；
- 例外不得成为普通部队的基础部署方式。

理由：这套系统的乐趣来自位置与时间，任何绕过两者的机制都在拆自己的地基。

## 五、兵营的生产与驻军

**[确认]** 兵营是军事生产与组织节点，不是"刷兵器的按钮"。基本流程：兵营训练 → 进入驻军/预备队 → 按方针或玩家指令出营 → 沿地图真实行军 → 进入战斗。

**[方向]** 兵营可设长期方针：边境巡防、驻守本地、前线增援、保留预备。

**[方向]** 常规部队自动部署与玩家保留预备队相结合（具体比例未验证）。

## 六、部署与调动的区别

| 操作 | 含义 |
|---|---|
| 部署 | 把驻军/预备力量从实际生产、驻扎地点投入地图 |
| 调动 | 已经在地图上的棋子改换行军目标 |
| 重新部署 | 棋子撤回、整备后，再从合法位置出发 |

**[确认]** 不允许普通部队隔空投送。南部兵营的部队不可能瞬间出现在北部边境，必须真实经过地图空间。

**[确认]** 由此军事建筑位置直接产生战略：后方安全但增援慢、前线增援快但易被袭、交通不便的据点价值受限。军事建筑布局本身就是构筑选择。

## 七、如何限制规模

**[确认]** 不设全文明统一的兵营硬上限。

**[方向]** 通过三种约束：人口/兵源（能训多少兵）、军事组织能力（能高效运转多大规模）、资源与空间（产能、位置与机会成本）。

**[待实验]** 军事组织能力软上限：玩家可以超出高效规模继续建设，代价应为效率下降与负荷上升，而不是系统禁止建造。

**[确认] 兵营数量不等于军队数量**：兵营决定生产效率与增援位置；军队规模由人口、资源与文明规则决定。不能规定"一座兵营最多三支部队"。

### 2026-10-25 修正：约束不挂在"玩家注意力"上

**[确认]** 本轮讨论曾提出"指令带宽上限"（同时可挂的有效指令数）作为软上限的落点，**该方案被否决**。

理由：正常状态下棋子是自动运行的，干预是例外而不是例行；把上限挂在玩家注意力上，会让游戏变成"管理注意力"的资源管理游戏，与"看着它跑，关键时刻出手"的核心体验相反。

**[方向]** 修正后的三条约束：

| 约束 | 落点 | 作用 |
|---|---|---|
| 军队规模 | **维持成本**（每支在野战团的日常消耗） | 堆兵被每日的账压住，而不是被玩家手速压住 |
| 干预能力 | **命令延迟**（传令/协调需要时间，距离越远越慢） | 到处都能救火变成"只能预判到的地方才救得下来" |
| 组织能力 | **命令延迟 + 增援速度 + 训练效率** | 超过高效规模后命令开始变慢、增援排队，但不禁止 |

**[方向]** 判据：一局里玩家真正动手的次数应该是个位数到十几次。如果玩下来每分钟都在点，是设计错了，不是玩家勤快。

## 八、卡牌如何介入军事

| 构筑对象 | 例子 |
|---|---|
| 棋子行为 | 改变索敌、追击、协同规则 |
| 棋子能力 | 冲锋、反击、击杀成长 |
| 兵营生产 | 改变训练方式、速度、兵种 |
| 兵营方针 | 自动增援、自动驻守、保留精锐 |
| 军事组织 | 提升组织能力、改变动员条件 |
| 特殊部署 | 战旗集结、墓地复生、传送协议 |

**[确认]** 普通棋子不必须靠抽卡生成；普通军事指令也不需要每次抽牌。卡牌决定军队**能做什么**与军事体系**如何运行**，玩家的战术操作决定这些能力**如何发挥**。

## 十、尚未定稿：一支战团的完整生命周期

这是下一阶段最优先要定的东西。五个问题与当前推荐（全部 [待定]，未验证）：

1. **训练完成后的位置**：推荐"进驻军池 + 营地营帐占位可视化，出营才实例化"。理由：同屏棋子预算有限（性能与可读性），但玩家仍能看见在营兵力。
2. **驻军占不占格、最多驻多少**：不占格；容量由驻军点的**补给覆盖**决定（每支每日消耗 X），而不是兵营等级。
3. **受损恢复**：撤离后整备，不在战斗中回血。让"撤退"成为有成本的战术选择。
4. **撤退失败**：不做逃跑判定。撤退就是下达移动指令回家，敌人按自己的索敌/追击规则决定咬不咬——"被咬住"是规则的自然结果。
5. **能否合并**：推荐允许同兵种合并为老兵团，作为**微操降压阀**（管 5 个大队而不是 20 个小队），并与"击杀成长"咬合；规模上限挂在组织能力上。

## 十一、本轮实验实现（experiments/tribe-opening）

2026-10-25 在 `experiments/tribe-opening` 里落了上述设计的骨架，**不是正式游戏**，也未并入 `game.html`：

- 兵营：实体建筑、占格阻挡、训练扣食物、固定 tick 后进驻军池、出营落在相邻格且驻守点 = 兵营。
- 四条方针：驻守本地 / 边境巡防 / 前线增援 / 保留预备，全部只看距离与计数。
- 命令延迟：`world.orderDelay`（试玩 = 2，离营 >4 格 +1），在途期间棋子继续自主行动。
- 军粮：每支在野战团每天 +1 食物；同屏预算 24 支。
- 验证：`tests/tribe-opening-military.test.js` 14 项确定性测试，含 P4"即时命令 vs 延迟命令"的救场对照。
- 细节与全部实测数据见 [../experiments/tribe-opening/README.md](../experiments/tribe-opening/README.md)。

**[实验] 明确未做**：碰撞与包围、战团编组、多兵营布局、不同文明的军事差异、兵营被袭与停产、整备与合并。
