# 卡牌 × 世界规则：第一个可复现实验

范围：`src/card-world-experiment.js` 与 `tests/card-world-experiment.test.js`，与地图组现有 `world.js`、主入口、渲染完全隔离。

**设计问题：** 同一张牌不选择“森林模式/敌人模式”，只对目标施加世界干预：`spark` 增加热量 55；`rain` 增加湿度 45。每次调用 `stepSimulation`，统一检查燃料、湿度、热量、邻居燃烧状态，由世界规则决定点燃、蔓延或熄灭。

**不是定稿：** 数值阈值和结算步长均为测试常量；不是完整火灾物理、文明时钟、卡牌成本、抽取/来源/概率波，也没有把 `world.js` 地形直接映射为燃料/湿度。刻意不改主游戏，以免抢地图组定义权。

运行 `npm test` 或 `node --test tests/card-world-experiment.test.js`。验收先看：同牌跨环境、邻接蔓延、下雨熄火、顺序无关、非法动作不修改状态。下一步再讨论适配现有世界数据的只读投影与事件回写边界。

## 第二步：命令 → 事件 → 结算屏障（独立实验）

新增 `src/card-command-queue.js`、`tests/card-command-queue.test.js`。创建方式为 `createCardQueue(simulation)`，`submit({id,card,q,r})` 只验证并排队，世界状态不变；`flush()` 将待处理命令冻结成一批，按提交次序执行全部卡牌干预，之后**恰好进行一次** `stepSimulation`，返回前后快照、执行列表和变化清单。

每个已接受的命令 ID 在队列生命期内只能使用一次（防误重复提交）；无效卡牌、越界目标或非法坐标不会进入队列。空屏障也推进一次实验 tick。事件顺序：若有命令，则多个 `card` 事件后接一个 `settlement` 事件。

**约束与未做：** 这是实验局部的事务边界，尚不支持执行中撤销、持久化队列、多执行者冲突、卡牌获得费用、冷却或优先级，也没有世界账本与地图写回；命令在屏障开始前已验证，但若外部代码擅自并发修改底层 Map，不提供强事务隔离。此处固定的出牌顺序不是正式裁决规则。

执行 `npm test` 验证已有测试与新测试。浏览器游戏入口仍不依赖它，保持和地图组分离。下一阶段可设计只读投影适配层，使现有地形只提供燃料/湿度等规则所需输入，但要先与地图组对齐字段来源。
